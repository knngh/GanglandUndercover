# 双人真人视角走查清单（D-1 / D-2）

> 状态：**待执行**。本轮已完成 Relay 自动化门禁，但尚未启动两个带窗口的真人客户端，因此未把真人视角步骤标记为通过。
> 目标：两名真人从入口进入同一局，确认身份简报、任务反馈、会议/投票和结算在 Host/Client 两个视角均可读、可操作。

## 前置条件

- [ ] Unity Editor/Relay 服务可用，`run-relay-twoprocess.sh` normal 能生成 Host/Client XML。
- [ ] Host 和 Client 使用独立进程/独立工程 Library。
- [ ] 记录开始时间、提交版本、Unity 版本、网络环境和屏幕分辨率。

## 操作步骤与验收

| 步骤 | Host 视角 | Client 视角 | 证据/备注 |
| --- | --- | --- | --- |
| 1. 入口 | 从菜单进入 Lobby，创建房间 | 输入房间码并加入 | 连接耗时、是否重复点击 |
| 2. Ready | Host 看到自己和 Client，开始按钮状态正确 | Client Ready 后状态同步 | 两端玩家名/人数一致 |
| 3. 身份简报 | 显示身份、阵营目标和第一步提示 | 显示身份、阵营目标和第一步提示 | 文案不截断、不遮挡操作按钮 |
| 4. 行动 | 完成一个任务，看到进度/反馈 | 完成一个任务，看到进度/反馈 | 任务锁、距离、完成提示 |
| 5. 会议 | 报告尸体或发起紧急会议 | 收到会议状态和证据墙 | 会议原因、倒计时、席位均可读 |
| 6. 投票 | 选择目标并提交 | 选择目标并提交 | 已投票反馈、结果动画、不可重复提交 |
| 7. 结算 | 显示胜负、原因和身份揭示 | 显示胜负、原因和身份揭示 | 结算文案与双方一致 |
| 8. 重开 | 返回 Lobby 或重开下一局 | 跟随返回 Lobby 或重开 | 不残留旧玩家、旧投票、旧 UI |

## 记录字段

- 连接耗时：Host 创建、Client 加入、双方 Ready、开始对局各自耗时。
- 可读性：身份、目标、任务、会议、投票、结算六类 UI 逐项记录 `PASS / FAIL`。
- 阻塞：无法点击、状态不同步、重复点击、卡在阶段、断线恢复分别记录。
- 网络：进程退出码、日志中的异常/断线、Host migration 是否触发。
- 问题分级：P0 崩溃/卡死；P1 无法完成主流程或关键信息不可读；P2 可绕过的体验问题。
