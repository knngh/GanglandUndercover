## 一、总体设计方针

### 1.1 音色世界观

Gangland Undercover 的音频世界观：**香港港区夜雨霓虹 × 警匪暗战 × 像素怀旧**。

| 维度 | 规范 |
|------|------|
| 整体风格 | 现代电子 + 轻微 Lo-Fi / 像素感（非 8-bit chiptune） |
| 合成器类型 | FM 合成（锐利短音） + 减法合成（暖底） + 少量采样（现实击打声） |
| 混响 | 小空间混响（模拟港区建筑内部），不是大厅混响 |
| 频率重点 | 中高频清晰（UI 反馈），低频不浑浊（不影响语音通讯） |
| 音量平衡 | 所有 SFX 峰值 -6dBFS，RMS -18dBFS（留 headroom 给叠加播放） |

### 1.2 参考音色

| 参考游戏/音源 | 对应什么 |
|--------------|---------|
| *Among Us* UI 音效 | 短促、清脆、不抢戏的 UI 反馈 |
| *Katana ZERO* 合成器音色 | 霓虹感、暗黑合成器底 |
| *Hotline Miami* 击打/击杀 | 暴力但不写实的像素化暴力音 |
| *Celeste* SFX | 像素风格音效的最佳实践（短、有音高、有情感） |

### 1.3 文件规范

| 属性 | 值 |
|------|-----|
| 格式 | `.ogg` (Vorbis) |
| 声道 | **Mono**（所有 SFX） |
| 采样率 | 44100 Hz |
| 位深 | 16-bit |
| 质量 | Vorbis q=0.5 (50%) |
| 最大文件大小 | 200 KB / 文件 |
| 命名 | `sfx_{category}_{event}.ogg`（对齐 E7 §1.4） |
| 峰值 | -6dBFS |
| 头部静音 | 0 ms（零延迟，Decompress On Load） |
| 尾部静音 | 自然衰减，不额外加静音 |

## 二、15 个 SFX 逐项设计

### 2.1 UI 音效（4 文件）

---

#### #1 UI 点击 — `sfx_ui_click.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 0.08-0.12s |
| **音色描述** | 短促清脆的"咔嗒"声。FM 合成，正弦波基频 800Hz，快速指数衰减。类似轻触机械键盘，但不那么重。 |
| **频率包络** | 800Hz → 1200Hz（0.02s 上升）→ 200Hz（0.08s 衰减） |
| **振幅包络** | Attack=0ms, Decay=80ms, Sustain=0, Release=0 |
| **音高感** | 轻微有音高，但不形成旋律感 |
| **参考** | Among Us 按钮点击音，但更轻、更有"现代 UI"感 |
| **触发场景** | 所有按钮点击：主菜单选角、大厅操作、设置调整 |
| **播放次数** | 高频（一局游戏可能 50+ 次），不能听感疲劳 |
| **特别要求** | 听 50 次不烦——这是最重要的验收标准 |

---

#### #2 UI 确认 — `sfx_ui_confirm.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 0.2-0.3s |
| **音色描述** | 正向确认音。两个音叠加：低频暖底（三角波 400Hz）+ 高频"叮"（正弦波 1600Hz）。结尾微微上扬（+50 cents pitch bend）。 |
| **频率包络** | 低频 400Hz 衰减 → 高频 1600Hz 0.05s 延后出场 |
| **振幅包络** | Attack=10ms, Decay=200ms |
| **情感目标** | 「操作成功」「被接受了」——正向、不浮夸 |
| **触发场景** | 创建房间成功、加入房间成功、设置保存、开始游戏确认 |
| **注意** | 不能与 UI 错误音混淆（确认 = 上扬，错误 = 下沉） |

---

#### #3 UI 错误 — `sfx_ui_error.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 0.25-0.35s |
| **音色描述** | 低沉"嗡嗡"拒绝音。方波 200Hz + 轻微噪声 burst。音高结尾下沉（-100 cents）。略带 brassy 质感。 |
| **频率包络** | 200Hz 方波 → 结尾 bend 到 150Hz |
| **振幅包络** | Attack=5ms, Decay=300ms |
| **情感目标** | 「被拒绝了」「做不到」——不刺耳但明确否定 |
| **触发场景** | 加入满员房间、无效操作、超时 |
| **注意** | 不能太刺耳。用低频表达拒绝，避免高频蜂鸣 |

---

#### #4 UI 通知 — `sfx_ui_notify.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 0.4-0.6s |
| **音色描述** | 两段式通知音。第一声"叮"（1600Hz，0.1s）→ 0.05s 静默 → 第二声"叮"（1800Hz，0.1s）。类似手机通知但更"像素风"。用 triangle wave 而非 sine（更有像素味）。 |
| **频率包络** | 第一声 1600Hz→衰减、第二声 1800Hz→衰减 |
| **情感目标** | 「注意！重要信息到了」——引起注意但不惊吓 |
| **触发场景** | 破坏发生通知、紧急会议召集、尸体被发现 |
| **特别要求** | 与 UI Click 有明确音色区分，玩家听一声就知道是通知而非点击 |

---

### 2.2 任务音效（2 文件）

---

#### #5 任务开始 — `sfx_task_start.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 0.5s |
| **音色描述** | 任务界面弹出音。中低频上升扫频（200Hz→600Hz） + 高频"唰"声（白色噪声经过带通滤波 2000-4000Hz）。类似科幻 UI 面板启动，但更短、更克制。 |
| **频率包络** | 扫频 200→600Hz（0.3s），噪声 burst 0.15s |
| **情感目标** | 「进入专注状态」——界面弹出 + 任务开始的双重信号 |
| **触发场景** | 玩家按下交互键开始任意任务 |
| **空间化** | 2D 全局播放（玩家注意力聚焦到任务 UI） |

---

#### #6 任务完成 — `sfx_task_complete.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 1.0s |
| **音色描述** | 三音上行琶音（C5→E5→G5，正弦波）。每个音 0.15s，音间 0.05s 间隔。结尾加轻微混响尾音（0.3s）。这是游戏中**最正向**的音效——任务完成=进度推进。 |
| **频率** | 523Hz→659Hz→784Hz（C5→E5→G5 大调和弦分解） |
| **振幅包络** | 每个音 Attack=10ms, Decay=130ms |
| **情感目标** | 「做完了！有成就感」——不过度庆祝，但明显正向 |
| **触发场景** | 任意小游戏任务成功完成 |
| **注意** | 如果在 2 秒内连续触发（快速完成两个任务），第二个播放时不应与第一个叠加——前一个被截断 |

### 2.3 游戏事件音效（3 文件）

---

#### #7 击杀 — `sfx_kill.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 0.6-0.8s |
| **音色描述** | 暴力但不写实的"像素化击杀音"。三层叠加：(1) 低频冲击 80Hz 鼓点 0.1s，(2) 中频"噗"声（噪声 burst 400-800Hz 0.2s），(3) 高频"嘶"衰减（粉红噪声 0.5s fade）。参考 *Hotline Miami* 击杀音但不那么写实血腥。 |
| **频率** | 低频 80Hz → 中频 400-800Hz → 高频 noise fade |
| **振幅包络** | 冲击 100ms → 身体音 200ms → 衰减 500ms |
| **情感目标** | 「有人被杀了」——冲击感，但不是恐怖氛围。像素游戏的暴力应该是风格化的。 |
| **触发场景** | 黑帮玩家成功击杀目标 |
| **空间化** | 3D（`PlayClipAtPoint`），击杀位置衰减。远距离玩家听到的是低通过滤版本。 |
| **特别要求** | 不被背景音乐淹没——80Hz 鼓点要穿透混音 |

---

#### #8 尸体报案 — `sfx_body_report.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 0.8-1.0s |
| **音色描述** | 警报感但不刺耳。快速音阶上升（C4→C5 半音阶，0.3s）+ 最后"哔——"长音（1200Hz 方波，持续 0.4s 然后切断）。警笛感但像素化处理。末尾切断是关键的"猛然"效果。 |
| **频率** | 半音阶 262→523Hz（0.3s）+ 1200Hz 方波长音（0.4s） |
| **情感目标** | 「出事了！马上开会！」——紧张警报，不惊慌 |
| **触发场景** | 玩家发现尸体并按下报案按钮 |
| **空间化** | 2D 全局播放（所有玩家都需要听到） |

---

#### #9 紧急会议 — `sfx_emergency.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 1.2-1.5s |
| **音色描述** | 比尸体报案更紧迫的警报。双音交替（800Hz ↔ 1000Hz，每 0.15s 切换，重复 4 次）→ 最后长音 1200Hz 0.3s → 切断。类似潜艇紧急下潜警报，但音色更电子。 |
| **频率** | 800Hz/1000Hz 交替 ×4 + 1200Hz 结尾长音 |
| **节奏** | 交替周期 0.15s × 4 = 0.6s，长音 0.3s |
| **情感目标** | 「有人按了紧急按钮——必须停止一切，立刻集合」 |
| **触发场景** | 玩家在会议冷却期外按下紧急会议按钮 |
| **注意** | 与 #8 尸体报案要能区分——紧急会议更急促、更电子、更有"人为拉响警报"感 |

---

### 2.4 会议/投票音效（3 文件）

---

#### #10 会议开始 — `sfx_meeting_start.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 1.5-2.0s |
| **音色描述** | 氛围转场音。低频持续 drone（80Hz 正弦波，fade in 1.5s）+ 屏幕闪红同步的 3 声"咚"（鼓点 100Hz，间隔 0.4s）。结束后直接切入会议 BGM。 |
| **频率** | Drone 80Hz + 鼓点 100Hz ×3 |
| **节奏** | 鼓点间隔 0.4s，"咚——咚——咚" |
| **情感目标** | 「所有人停下手头的事，进入审判状态」 |
| **触发场景** | 尸体报案或紧急会议触发后，进入会议界面时 |
| **注意** | 最后一声鼓点与会议 BGM 的 Layer 3 起始重叠（crossfade 0.5s） |

---

#### #11 投票 — `sfx_vote_cast.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 0.2-0.3s |
| **音色描述** | 投票卡牌翻转音。轻脆的"啪嗒"声——纸张翻动 + 轻微点击。采样质感：厚纸片打击桌面（但像素化处理：bitcrush 到 8-bit 质感）。 |
| **合成方式** | FM 合成模拟纸张打击——噪声 short burst(100-500Hz) + 高频叮 2400Hz 10ms |
| **情感目标** | 「我一票投出去了」——有分量的决定感 |
| **触发场景** | 每位玩家投出自己的一票 |
| **播放规则** | 多个玩家几乎同时投票：允许叠加（每人一票=每票一音，叠加是设计意图——制造"大家纷纷投票"的氛围） |

---

#### #12 玩家被淘汰 — `sfx_player_ejected.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 1.0-1.2s |
| **音色描述** | 沉重下行音。低频"咚"（80Hz，0.2s）→ 下行滑音（500Hz→100Hz，0.5s）→ 最后"啪"切断（噪声 burst，0.1s）。类似 *Among Us* 的 eject 音效，但更低沉、更有港片"被带走"的黑暗感。 |
| **频率** | 80Hz 咚 → 500→100Hz 滑音 → 噪声 burst |
| **情感目标** | 「有人被投票出局了——沉重、不可逆」 |
| **触发场景** | 投票结果：某玩家被多数票淘汰 |
| **注意** | 如果平票/跳过，不播放此音效，改用 A4 阶段的 `sfx_vote_skip.ogg` / `sfx_vote_tie.ogg` |

### 2.5 结算音效（3 文件）

---

#### #13 警方胜利 — `sfx_victory_police.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 3.0-4.0s |
| **音色描述** | 庄严但简洁的胜利曲。警蓝色调：大调和弦分解（C→E→G→C' 上行，正弦波，每音 0.6s）+ 轻微军鼓滚奏（噪声 burst 模拟，0.5s）。不过度庆祝——警方胜利是"正义得到伸张"的庄重感。 |
| **和弦** | C 大调 I→III→V→I' 分解 |
| **音色** | 正弦波主旋律 + 轻微 noise 打击节奏 |
| **情感目标** | 「正义胜利了」——庄重、不是狂欢 |
| **触发场景** | 警方阵营达成胜利条件（所有黑帮被投票淘汰或任务完成） |

---

#### #14 黑帮胜利 — `sfx_victory_gang.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 3.0-4.0s |
| **音色描述** | 邪魅暗黑胜利音。小调五声音阶下行（Eb→C→Bb→G，方波，每音 0.6s）+ 低频 drone 80Hz 持续。比警方胜利更"阴沉"，但同样不过度庆祝——黑帮胜利是"规则被颠覆"的黑暗满足感。 |
| **音阶** | Eb 小调五声下行 Eb→C→Bb→G |
| **音色** | 方波（比警方正弦波更"锋利"）+ drone |
| **情感目标** | 「黑暗面赢了」——邪魅、不嚣张 |

---

#### #15 失败 — `sfx_defeat.ogg`

| 属性 | 值 |
|------|-----|
| **时长** | 2.0-2.5s |
| **音色描述** | 不论阵营，你输了。下行小三度滑音（400Hz→200Hz，1.0s）+ 沉闷鼓点 ×2（60Hz，间隔 0.5s）+ 最后低频 drone fade（0.5s）。不像 *Price is Right* 失败音那么滑稽——这是"你没能完成任务"的沉重感。 |
| **频率** | 400→200Hz 滑音 + 60Hz 鼓点 ×2 |
| **情感目标** | 「你输了」——沉重、不嘲讽 |
| **触发场景** | 玩家所在阵营失败时，个人听到的结算音 |

> **区分逻辑**：警方玩家听到的是"警方胜利" + "个人表现"；黑帮玩家听到的是"黑帮胜利" + "个人表现"；失败方玩家听到的是"失败" + 对方阵营的胜利音（如果他们还在房间里）。

## 三、样品先行策略

### 3.1 首批样品（3个，2天内交付评审）

| 样品 | 选择理由 |
|------|---------|
| `sfx_ui_click.ogg` (#1) | 最高频使用，听感疲劳是最大风险。样品通过 = 整个 UI 音效系列的基准。 |
| `sfx_kill.ogg` (#7) | 游戏核心事件的音效，需平衡"暴力感"和"像素风格"。最难拿捏的项目。 |
| `sfx_meeting_start.ogg` (#10) | 氛围转场音，考验音效→BGM过渡设计。如果这个成立，其他转场音就不担心。 |

### 3.2 样品评审标准

| 评审维度 | 通过条件 |
|----------|----------|
| 音色一致性 | 三个音放在一起，有统一的"像素暗黑霓虹"世界观感 |
| 情感准确 | Click 够轻不烦、Kill 有冲击不血腥、Meeting 有氛围不拖沓 |
| 技术合规 | .ogg Vorbis q=0.5、Mono 44100Hz、-6dBFS peak、无爆音/削波 |
| 文件大小 | Click < 30KB、Kill < 80KB、Meeting < 200KB |

### 3.3 评审不通过的处理

样品退回修改，修订轮最多 2 轮。如果 2 轮后仍不通过 → 换参考音源、重新定义音色方向。

## 附录：音效设计师 FAQ

**Q: 为什么要 "像素风格" 但不是 chiptune？**  
A: 游戏是像素美术，但音色完全 chiptune（8-bit 方波三角波）会有廉价感。我们追求的是——听起来像现代电子音效，但经过轻微 bitcrush 处理，有 Lo-Fi 纹理。用 *Katana ZERO* 的合成器质感作为参考。

**Q: 击杀音效要多 "暴力"？**  
A: *Hotline Miami* 的击杀音是写实血腥方向——我们这个不要。我们的击杀音应该让人感到"有人被干掉了"但不会不适。用低频冲击 + 像素化的噪声 burst，避免粘稠的血肉感。游戏年龄分级友好。

**Q: 15 个文件可以一次交付吗？**  
A: 不建议。先出 3 个样品（Click/Kill/MeetingStart），评审定调后再出剩余 12 个。这样如果方向不对，只需要返工 3 个而不是 15 个。

**Q: 需要做空间化吗？**  
A: 击杀 (#7) 需要 3D 空间化（靠近 vs 远离听到的版本不同）。其余全部 2D 全局播放。Unity 中 3D 空间化由 `AudioManager.PlayClipAtPoint()` 处理，你只需交付 mono 文件，空间化是引擎侧参数调整。
