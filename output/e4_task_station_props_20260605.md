## 1. 通用设计规范

### 1.1 任务站通用视觉规则

| 属性 | 规范 |
|------|------|
| 基座尺寸 | 32×48 px（宽×高），世界单位 1×1.5 |
| 交互光环 | 发光脉冲环（α=0.4，2Hz，颜色根据状态变化） |
| 状态灯 | 任务站顶部小型 LED 指示灯 |
| 名称标签 | 任务站下方 14px 白色文字（不遮挡道具） |
| 破损坏线 | 被破坏时覆盖红色斜线纹理和火花粒子 |
| 完成标记 | 完成后显示绿色 ✓ 和灰色淡化效果 |

### 1.2 任务站状态视觉

| 状态 | 光环颜色 | LED 颜色 | 交互提示 | 额外反馈 |
|------|----------|----------|----------|----------|
| 空闲（可交互） | 霓虹黄 `#f4a236` | 绿色闪烁 | 「按 E 开始任务」 | 无 |
| 其他玩家使用中 | 灰色 `#7f8c8d` | 黄色常亮 | 「任务进行中」 | 周围角色不可交互 |
| 已完成（本玩家） | 绿色 `#2e8b57` | 绿色常亮 | 「任务已完成」 | 灰色淡化覆盖 |
| 被破坏 | 红色 `#c0392b` | 红色闪烁 | 「破坏！按 E 修复」 | 红色斜线纹理 + 火花 |
| 被破坏后修复中 | 蓝色 `#2d6fba` | 蓝色闪烁 | 「修复中…」 | 进度条显示 |
| 关机/禁用 | 无光环 | 无灯 | 无提示 | 全灰覆盖 |

### 1.3 命名规范

```
prop_task_{tasktype}_{state}.png
  例: prop_task_wire_idle.png
      prop_task_wire_active.png
      prop_task_wire_complete.png
      prop_task_wire_broken.png
```

## 2. 11 种任务站详细定义

### 2.1 Wire / Repair：电线修复配电箱

**任务名称**：线路修复 / Wire Repair  
**代码类**：`WireTask`  
**对标 Among Us**：电线连接（Wires）  
**部署房间**：电房、后巷、配电间

#### 视觉描述

一个壁挂式配电箱，金属灰色外壳（32×48 px），正面可见：
- **箱体**：铝合金色 `#8899aa`，四边 2px 边框，铆钉四角各一个。
- **内部电线**：4 组彩色线缆从箱内伸出，杂乱交叉：
  - 红线 `#e74c3c`、蓝线 `#3498db`、黄线 `#f1c40f`、绿线 `#2ecc71`
  - 线缆用 2px 粗曲线绘制，交叉处无遮挡（暗示需要整理）
- **状态灯**：箱体右上角圆形 LED（直径为 4px）。
- **警示标签**：箱体左下角有黄色三角 ⚠ 标签（8×8 px），上写「高压」。
- **火花粒子**（使用中 / 损坏）：箱体左下方偶尔冒出 3-5 个橙黄色小火花（VFX sprite 2×2 px）。

#### 各状态变化

| 状态 | 视觉变化 |
|------|----------|
| 空闲 | LED 绿色闪烁、光环霓虹黄 |
| 使用中 | LED 绿色快速闪烁、火花粒子偶尔冒出、线缆有摆动动画 |
| 完成 | LED 绿色常亮、线缆变整齐（平行排列）、绿色 ✓ 标记 |
| 破坏 | LED 红色闪烁、火花密集冒出、红色斜线遮罩覆盖箱体、线缆断成几段 |

#### 交互 UI 皮肤
- 连线界面应有电线纹理背景（金属配电箱内部视角）。
- 左右两侧彩色端口（红/蓝/黄/绿各 4 个）。
- 中间预制绝缘胶带缠绕效果。

### 2.2 Keypad：壁挂式数字密码键盘

**任务名称**：密码输入 / Keypad Entry  
**代码类**：`KeypadTask`  
**对标 Among Us**：安全门密码  
**部署房间**：海关/指挥区、监控室、金融楼

#### 视觉描述

一个壁挂式数字面板（32×48 px），深色外壳：
- **面板本体**：深灰色 `#3a3d42`，4px 圆角，表面微凸。
- **屏幕**：面板上部 24×8 px 深绿色 LCD 屏幕（`#0f380f`），显示当前输入位数（4 个圆点或星号）。
- **按键**：3×3 + 1 布局（10 个按键）：
  - 按键尺寸：6×6 px，深色 `#1a1c2c` 底色 + 白色数字。
  - 布局：
    ```
    [1] [2] [3]
    [4] [5] [6]
    [7] [8] [9]
        [0]
    ```
- **LED 灯**：屏幕上边缘有一个 4px 红色/绿色 LED 指示灯。
- **清除键**：0 键左侧有红色小三角清除按钮（◀）。
- **确认键**：0 键右侧有绿色小三角确认按钮（▶）。

#### 各状态变化

| 状态 | 视觉变化 |
|------|----------|
| 空闲 | LED 绿色闪烁、LCD 显示 "----" |
| 使用中 | LED 绿色快速闪烁、LCD 显示已输入位数（如 "**--" 表示输入 2 位） |
| 完成 | LED 绿色常亮、LCD 显示 "PASS" |
| 失败（3 次错误） | LED 红色闪烁 3 次、LCD 显示 "FAIL"、面板变灰 |
| 破坏 | LED 红色闪烁、按键随机亮灭（glitch 效果）、红色遮罩 |

#### 交互 UI 皮肤
- 大号 9 宫格按键 UI + 底部 0 键 + 清除/确认。
- LCD 显示实时输入（圆点遮罩）。
- 剩余尝试次数计数器。

### 2.3 SwipeCard：刷卡式门禁读卡器

**任务名称**：刷卡验证 / Swipe Card  
**代码类**：`SwipeCardTask`  
**对标 Among Us**：刷卡（Swipe Card）  
**部署房间**：证物室、指挥广场、审讯室

#### 视觉描述

一个壁挂式门禁读卡器（32×40 px），下有卡片槽：
- **读卡器本体**：米白色 `#d5d8dc`，矩形，4px 圆角。
- **屏幕**：读卡器上方 20×10 px 小 OLED 屏幕（蓝色调 `#1a3a5c`），显示文字。
- **刷卡槽**：读卡器中部横贯黑色凹槽（2px 高），用于模拟刷卡轨迹。
- **指示灯**：刷卡槽右侧红/绿色 LED 灯。
- **证件卡**：一张 12×8 px 的矩形卡片从右侧伸出：
  - 卡片底色：白色 `#ecf0f1`
  - 卡片照片：5×5 px 灰色头像占位
  - 磁条：卡片底部 1px 黑色横线
- **底座线缆**：读卡器下方有 1 根灰色线缆连接墙内。

#### 各状态变化

| 状态 | 视觉变化 |
|------|----------|
| 空闲 | 屏幕显示 "READY"、LED 绿色闪烁、卡片在槽外 |
| 使用中 | 屏幕显示 "SWIPE"、卡片沿槽滑动动画、LED 黄色闪烁 |
| 成功 | 屏幕显示 "OK"、LED 绿色常亮、卡片退回 |
| 失败（速度/方向错误） | 屏幕显示 "ERR"、LED 红色闪烁、卡片弹回原位 |
| 破坏 | 屏幕显示乱码 "????"、LED 红色闪烁、红色遮罩 |

#### 交互 UI 皮肤
- 水平滑块 UI：引导线 + 滑动卡片（按住拖动）。
- 绿色目标速度区域指示（对标 Among Us 刷卡节奏）。
- 卡片图片使用警徽/龙头图案（按玩家阵营不同）。

### 2.4 Scan：平板式扫描仪

**任务名称**：证据扫描 / Evidence Scan  
**代码类**：`ScanTask`  
**对标 Among Us**：MedBay 扫描  
**部署房间**：证物室、地下诊所、法医科

#### 视觉描述

一台桌面扫描仪（48×32 px，横向），放在台面上：
- **扫描仪底座**：浅灰色 `#bdc3c7`，矩形扁平底座（48×20 px），底部有 4 个橡胶脚垫。
- **扫描玻璃面**：底座中央 36×14 px 半透明玻璃面板（淡蓝色 `rgba(100,180,255,0.15)`）。
- **扫描臂**：底座上方横置可移动扫描臂（48×4 px 灰色横梁），沿导轨从右向左移动。
- **证物袋**：玻璃面上放置一个 16×10 px 透明证物袋（透明底 + 白字标签），内含一件小证物（子弹壳 / 药片 / 指纹卡）。
- **扫描光条**：扫描臂下方有 1px 亮蓝色光条，扫描时发光。
- **指示灯**：底座右上角红/绿色 LED。
- **电线**：底座右侧有 1 根电源线。

#### 各状态变化

| 状态 | 视觉变化 |
|------|----------|
| 空闲 | 扫描臂停于右侧、LED 绿色闪烁、玻璃面微亮 |
| 使用中 | 扫描臂从左向右缓慢移动、光条亮蓝色发光、证物袋下有扫描路径波纹 |
| 完成 | 扫描臂归位右侧、LED 绿色常亮、玻璃面显示绿色 ✓ |
| 失败 | 扫描臂停在中间、LED 红色闪烁、证物袋被红色 X 覆盖 |
| 破坏 | 玻璃面碎裂纹理、LED 红色闪烁、扫描臂倾斜、红色遮罩 |

#### 交互 UI 皮肤
- 圆形扫描区域（对标 Among Us MedBay 扫描器）。
- 绿色安全区域环形高亮。
- 扫描环从外向内收缩，中间状态指示灯。

**任务名称**：数据下载 / Data Download

一台老式桌面电脑终端（40×48 px）：
- **显示器**：CRT 风格，深灰色外壳 `#4a4d52`，屏幕尺寸 28×22 px。
  - 屏幕底色：深蓝黑 `#0a0b12`。

| 失败（中断） | 屏幕显示 "CONNECTION LOST"、进度条红色、LED 红色闪烁 |

- 终端屏幕全屏 UI，模拟桌面 OS 界面。

- 下载速度波动效果（对标 Among Us Download Data）。

### 2.6 Sort：档案柜与分拣台

**任务名称**：档案分类 / File Sorting  
**代码类**：`SortTask`  
**对标 Among Us**：垃圾分类/整理柜子  
**部署房间**：证物室、档案室、专案办公室

#### 视觉描述

一个四层档案柜与分拣台组合（48×48 px）：
- **档案柜**：左侧 22×48 px 金属文件柜，米白色 `#e8e8e8`。
  - 4 层抽屉，每层有标签插槽（4×2 px 白色标签）。
  - 抽屉金属把手（2px 银色横条）。
  - 顶层抽屉半开，内有文件夹边角露出。
- **分拣台**：右侧 24×48 px 木质台面，台面颜色 `#8b6914`（木纹色）。
  - 台面有 4 个分类槽（各 10×10 px），槽口朝上。
  - 4 个槽位标签（从上到下）：
    1. 「已结案」(Closed Cases) — 绿色标签
    2. 「调查中」(Active) — 黄色标签
    3. 「待归档」(To File) — 蓝色标签
    4. 「机密」(Classified) — 红色标签
- **文件夹**：4 个 8×6 px 文件夹散落在台面或档案柜上：
  - 红色文件夹（案件编号 A-01）
  - 蓝色文件夹（案件编号 B-07）
  - 黄色文件夹（案件编号 C-14）
  - 绿色文件夹（案件编号 D-03）
- **标签贴纸**：文件夹正面有白色标签条（字体用小点模拟）。

#### 各状态变化

| 状态 | 视觉变化 |
|------|----------|
| 空闲 | 文件夹散落在台面、LED 绿色闪烁 |
| 使用中 | 其中一个文件夹被高亮（玩家选中的）、正确放入槽位后槽位变为绿色 |
| 完成 | 所有 4 个文件夹归入对应槽位、LED 绿色常亮、档案柜整齐闭合 |
| 失败 | 文件夹散落回桌面、LED 红色闪烁 |
| 破坏 | 文件夹洒落一地（范围更大）、档案柜抽屉全开、红色遮罩 |

#### 交互 UI 皮肤
- 4 个可拖拽卡片（文件夹）+ 4 个固定目标槽。
- 拖拽时半透明跟随鼠标。
- 正确匹配时吸附动画 + 绿色高亮。

### 2.7 Memory：记忆灯板

**任务名称**：记忆序列 / Memory Sequence  
**代码类**：`MemoryTask`  
**对标 Among Us**：记忆闪灯（Start Reactor 简化版）  
**部署房间**：电房、监控室、暗渠

#### 视觉描述

一块壁挂式记忆板（40×40 px）：
- **底板**：深灰色 `#2c3e50`，有均匀分布的网格线（1px 浅灰 `#5d6d7e`）。
- **灯格**：3×3 共 9 个圆形灯按钮：
  - 每个格子 10×10 px（含 1px 间距）。
  - 灯色：待机=暗灰 `#34495e`、亮起=霓虹蓝 `#3498db`、正确=绿 `#2ecc71`、错误=红 `#e74c3c`。
  - 按钮有微凸 3D 效果（高光 + 阴影各 1px）。
- **序列显示**：灯板上方 34×4 px LED 灯条，显示当前序列号（1-9）。

| 完成 | 所有灯依次变为绿色（从左到右点亮效果）、LED 绿色常亮 |
| 错误 | 点击错误的灯变红色 0.5 秒后恢复暗灰、LED 红色闪烁一下 |
| 破坏 | 所有灯随机闪烁（无规律）、红色遮罩覆盖 |

#### 交互 UI 皮肤
- 大号 3×3 网格灯板 UI（对标 Among Us Start Reactor 简化版）。
- 演示阶段：灯自动依次亮起（蓝色）。
- 复现阶段：点击灯格，正确=绿色闪烁，全部正确=完成。

- **面板**：深灰色金属 `#4a4d52`，4 个仪表呈 2×2 排列。
- **仪表 1—左上**：电压表（绿色刻度，红色指针）。
- **仪表 2—右上**：电流表（蓝色刻度，黄色指针）。
- **仪表 3—左下**：压力表（橙色刻度，白色指针）。
- **仪表 4—右下**：温度表（红色刻度，银色指针）。
- **仪表规格**（每个）：
  - 圆形表盘直径 14px，金属边框 1px。
  - 刻度线：外周 30°-150° 扇形区域，12 条刻度线。
  - 指针：2px 宽 × 8px 长细针，从中心辐射。
  - 目标区域：绿色弧段标记（约 15° 范围）。
- **旋钮**：面板下方中央有 1 个 8×8 px 圆形旋转旋钮（用于校准），带凸起纹路。
- **校准按钮**：旋钮右侧有小型「校准」按钮。

#### 各状态变化

| 状态 | 视觉变化 |
|------|----------|
| 空闲 | 所有指针在随机位置、LED 绿色闪烁 |

| 对齐 | 指针进入绿色区域时仪表变亮、边框闪绿色 |
| 完成 | 全部 4 个指针停在绿色区域、LED 绿色常亮 |
| 偏差 | 指针偏离目标区域、仪表边缘微红 |
| 破坏 | 所有指针疯狂摆动、仪表玻璃碎裂纹理、红色遮罩 |

#### 交互 UI 皮肤
- 4 个仪表盘的 2×2 大图 UI。
- 旋钮/滑块交互（拖动调整指针）。
- 绿色目标区域高亮。
- 对齐度百分比显示。

### 2.10 Asteroid（雷达追踪控制台）

**任务名称**：雷达追踪 / Radar Tracking  
**代码类**：`AsteroidTask`（待开发，建议重命名）  
**对标 Among Us**：清理陨石（Clear Asteroids）— 题材皮肤化  
**部署房间**：监控室、海关/指挥区、天台

> **重要设计决策**：原 Among Us 的「清除陨石」是科幻题材，不适合警匪题材。  
> 将其皮肤化为**雷达追踪控制台**：玩家不是射击陨石，而是在雷达屏上锁定并追踪可疑目标。

#### 视觉描述

一个大型桌面雷达控制台（48×40 px）：
- **控制台本体**：军绿色 `#4a6741`，楔形斜面（前低后高）。
- **雷达屏幕**：控制台前方 36×28 px 圆形屏幕（深绿色 `#0a1a0a`底色 + 辐射扫描线）。
  - 扫描线：从圆心向外旋转的亮绿色线（2px 宽，逆时针旋转，周期 2 秒）。
  - 网格：示意角度的放射线和同心圆（1px 暗绿色 `#1a3a1a`）。
  - 目标点：红色/橙色闪烁光点（3×3 px），数量 6-8 个，分散在雷达屏上。
- **追踪锁定框**：绿色十字准星 + 虚线矩形框（12×8 px），表示当前锁定目标。
- **摇杆**：控制台右侧有 12×8 px 小型跟踪球摇杆（类似 ThinkPad 小红点）。
- **按钮面板**：控制台左侧有 3 个矩形按钮（红/绿/橙，各 6×4 px）。
  - 红色「锁定」、绿色「追踪」、橙色「扫描」。
- **天线**：控制台顶部有 1 根小型碟形天线（8×16 px），微微摆动。

#### 各状态变化

| 状态 | 视觉变化 |
|------|----------|
| 空闲 | 扫描线旋转、目标点缓慢漂移、LED 绿色闪烁、屏幕显示 "RADAR STANDBY" |
| 使用中 | 扫描线加速旋转、目标点高亮、玩家操控的十字准星在屏幕上移动、已锁定的目标打勾 |
| 完成 | 全部目标锁定（十字准星 + ✓）、LED 绿色常亮、屏幕显示 "ALL TARGETS TRACKED" |
| 失败 | 目标飘出屏幕（消失）、LED 红色闪烁、屏幕显示 "TRACKING LOST" |
| 破坏 | 屏幕雪花噪点、扫描线消失、所有目标变灰色虚影、红色遮罩 |

#### 交互 UI 皮肤
- 全屏雷达界面：深绿色扫描屏 + 辐射线旋转。
- 鼠标移动控制十字准星。
- 左键点击锁定目标（对标 Among Us 射击陨石）。
- 目标数量倒计时：右侧显示 "剩余 3/8"。
- 时间限制条（对标原版：太慢会被雷达烧毁/目标逃脱）。

#### 命名建议
- 代码中建议重命名：`AsteroidTask` → `RadarTrackingTask`。
- 保持 `AsteroidTask` 作为历史类名别名，避免破坏现有引用。

### 2.11 EvidenceArchive：证据档案室

**任务名称**：证据归档 / Evidence Archive

**部署房间**：证物室、档案室

#### 视觉描述

一个大型证据储存区域（64×48 px，最大任务站）：
- **证据柜**：左侧 3 个并排金属档案柜（各 16×40 px），米白色 `#e8e8e8`：

| 破坏 | 证据柜抽屉全开/被撬、照片墙被撕毁（撕裂纹理）、证物散落地面、红色遮罩 |

#### 交互 UI 皮肤
- 两阶段 UI：
  1. **归档阶段**：拖拽证物袋到对应证物柜（类似 Sort 任务）。
  2. **证据链阶段**：在照片墙上连线关联证物（从一个照片拖到另一个照片，建立红线连接）。
- 背景使用案卷/档案纹理。
- 证据链完成时红线连成一个闭环。

public enum TaskStationState
{
    Idle,       // 空闲可交互

    Completed,  // 已完成
    Broken,     // 被破坏
