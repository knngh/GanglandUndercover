### 1.1 当前状态评估

**架构状态**：港区是唯一使用 `MapLayoutData` ScriptableObject 的地图（通过 Inspector 编辑），但代码中同时保留了 `OnlineMapService` 内的硬编码方法（`HarbourDistrictRooms()`、`TaskPositionFor()` 等）。两套数据源存在同步风险——如果 Inspector 中修改了 ScriptableObject 但忘记更新硬编码方法，会导致灰盒建造与任务逻辑不一致。

**美术状态**：
- `RoomDecorator.DecorateHarbourProps()` 为 12 个房间中的 9 个提供了道具装饰（索引 0/1/2/3/4/6/7/10/11），房间索引 5（金融楼）、8（指挥广场）、9（证物库）缺少专属道具。
- `KenneySpriteCatalog.MatchRoom()` 已覆盖全部 12 个港区房间关键词。
- `VerticalSliceStageOne` 在港区地图上叠加了高质量 3D Asset Store 建筑模型（监控室、茶餐厅、夜市、后巷、电房），但仅覆盖 5 个房间。

**问题清单**：
1. 金融楼、指挥广场、证物库 3 个房间无灰盒装饰道具（`RoomDecorator` 中缺 case）。
2. 暗线节点仅 4 个（硬编码在 `OnlineMapService` 中），少于警局的 4 个和九龙城寨的 5 个，与港区"大地图"定位不匹配。
3. 港区任务站 28 个位置全为硬编码坐标（`TaskPositionFor()` L220-248），无法通过 Inspector 调整。
4. 没有使用 `MapLayoutData` 的 `SightBlockers` 字段——港区无视线遮挡体定义。

### 1.2 可玩路线分析

**地图拓扑**（基于房间坐标与任务点分布推断）：

```
北区（y>3）：货柜场(0) — 海关(1) — 夜市(4) — 金融楼(5) — 电房(6)
                                          |
中区（y 0~3）：监控室(2) — 茶餐厅(3)    天台(7)
                  |              |
                  +--- 会议点 ---+
                                 |
南区（y<0）：证物库(9) — 指挥广场(8) — 后巷(10) — 地下诊所(11)
```

**动线问题**：
- **北区瓶颈**：货柜场(0)和海关(1)紧邻但入口均朝南，玩家从南区前往需绕行。电房(6)位于东北角极端位置，从会议点到电房步行距离约 20+ 世界单位，是全局最远任务点。
- **南区死角**：证物库(9)和地下诊所(11)分别位于西南和东南角落，两者之间无直接走廊连接，必须经指挥广场(8)中转。
- **中央走廊过于通畅**：茶餐厅(3)到指挥广场(8)之间缺少遮挡，从监控室(2)方向可以一览无余。

**建议**：
1. 在电房(6)和天台(7)之间增加一条捷径走廊，缩短东北象限通勤时间。
2. 证物库(9)和地下诊所(11)之间增加一条"地下水道"暗线连接，奖励探索行为。
3. 茶餐厅(3)和指挥广场(8)之间的中央通道增加 1-2 个视线遮挡体。

**架构状态**：
- 存在**三套**数据源：
  1. `PoliceStationMapLayout.cs`（静态工厂类 → 生成 `MapLayoutData`）
  2. `PoliceStationMap.cs`（`World/` 目录下，静态类，6 区域定义 + `Area` 枚举）
  3. `OnlineMapService.PoliceStationRooms()`（硬编码房间数组）
- 三套数据的坐标和尺寸一致，但维护成本高。`PoliceStationMap.Area.Armory` 枚举名为"武器库"，而 `PoliceStationMapLayout` 中已改为"监控室"——命名不一致。

**美术状态**：
- `PoliceStationInteriorBuilder.cs` 提供了**极其详细的**程序化室内装饰（6 个区域各有完整家具），包括接待台、长椅、单向玻璃、金属桌椅、证物箱、监视器墙、铁栅栏等。
- `RoomDecorator.DecoratePoliceProps()` 提供了简化的灰盒道具。
- 两套装饰系统并存：`PoliceStationInteriorBuilder`（精细3D）和 `RoomDecorator`（灰盒占位），运行时可能同时生成导致重叠。

**问题清单**：
1. 拘留室(4)和简报室(5)无监控摄像头覆盖（`PoliceStationMapLayout.Surveillance()` 仅 4 个，RoomIndex 0/1/2/3）。
2. 拘留室(4)只有 1 条走廊连接（审讯室↔拘留室），是全图最孤立的房间。
3. 暗线网络中，节点 2（证物室通风管）的 `ConnectedIndices` 为 `{0, 5}`，但总共只有 4 个节点（索引 0-3），索引 5 越界——这是 `PoliceStationMapLayout.Vents()` 中的一个 **BUG**。
4. 走廊"证物室↔监控室"尺寸 6.3 x 0.9，是全图最长走廊（横跨全图），缺少中间遮挡。

### 2.2 可玩路线分析

**动线问题**：
- **中央大厅过于开放**：大厅(0)连接 3 个方向（审讯室、证物室、简报室），是必经之路，但尺寸 3.2 x 2.4 偏小，多人交汇时拥挤。

1. 为拘留室增加一条直通走廊到证物室或大厅，避免完全死路。
2. 在长走廊中间增加一个"档案角"遮挡体，打断视线。
3. 简报室↔监控室走廊（0.9 x 3.3）较窄，可增加一个小型壁龛作为躲藏点。

- `RoomDecorator.DecorateKowloonProps()` 为全部 8 个房间提供了道具装饰。

**问题清单**：
1. 天台(5)和暗渠(7)各只有 1 个任务站，任务密度偏低。
2. 暗线节点 1（药材铺暗线）的 `ConnectedIndices` 包含索引 5，但总共只有 5 个节点（索引 0-4），索引 5 越界——与警局同样存在 **BUG**。

5. 监控覆盖中，药材铺(1)、麻将馆(2)、后巷(4)、天台(5)、地下钱庄(6) 五个房间无直接摄像头。

### 3.2 可玩路线分析

**地图拓扑**（来源：`KowloonWalledCityMapLayout.Corridors()` 走廊连接关系）：

```
北区：天台(5)
        |（天井楼梯）
      茶餐厅(0)
     /    |    \
药材铺(1) |   麻将馆(2)
    |     |      |
    |   天井(3)  |
    |   / | \    |
后巷(4)  |  地下钱庄(6)
         |
       暗渠(7)
```

**动线问题**：
- **茶餐厅是绝对枢纽**：茶餐厅(0)直接连接药材铺、麻将馆、天井、天台 4 个房间，所有南北交通必经此处。如果在此处被堵，基本无法绕行。
- **南区双角孤立**：后巷(4)和地下钱庄(6)分别位于西南和东南，两者之间需经天井(3)中转。
- **暗渠极端位置**：暗渠(7)位于极南 (0, -4.2)，仅通过一条 3.2 单位长通道连接天井，是最远的房间。

**建议**：
